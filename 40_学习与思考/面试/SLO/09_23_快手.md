## from面试官
1.为什么选择GRPO
```
1.（为什么用RL）证据、诊断和报告文本可以做RLVR，从而显式控制这三类目标，而不是继续通过SFT去fit正确答案；模型具备一定的能力，但是输出不稳定
2.（为什么选GRPO）能对同一病例采样多份报告，并用同一套医生确认的金标准进行打分；GRPO省去critic模型，节省开销；
--医生的审阅结果能多次复用；人工审阅和训练解耦，

new：
由于医生用来形成金标准的G份回答并没有直接参与GRPO训练，如果直接用来训练，会导致后续更新和pai_old偏离太多；
但是构造DPO是很自然的，为什么不用DPO？
我们的反馈自然形成多维、可计算的报告级评分，GRPO能直接把评分转化为组内相对优势，DPO还需要把评分转换成偏好对。
```

2.GRPO和RFT的区别，GRPO为什么有效果，为什么GRPO能起到“探索”的作用，和RFT的性能一样吗？
```
1.GRPO和在线RFT区别在于如何利用探索中得到的好坏样本。
--二者都有探索过程，即随机采样不同的token，形成不同的trace，再观察其奖励；
2.RFT将奖励用作样本筛选，通过交叉熵模仿入选结果；GRPO将奖励转化为组相对优势，使用PPO-style的目标来更新policy。后者能强化好的候选，也能利用相对差的候选给出负反馈。

--RFT是否也隐式抑制低分回答？
举个例子，假设对于trace的分叉点，对于A优于B、C，RFT的抑制对于B和C是一致的，但是GRPO是可以对B和C产生不同的感知的，对信号利用更充分。
```

## 讲述过程中存在的问题
1.reward hacking和奖励函数迭代的故事
```
1.希望生成的报告既能覆盖正确诊断，又不过度报病，同时保证证据和诊断一致；报告文本符合医生风格。
-因此最初根据金标准设计规则奖励，对FP、FN、证据缺失和不一致分别扣分。
2.hacking1：模型重复输出同一疾病，直至长度上限
-诊断评分时直接从报告中提取疾病集合，漏掉了对重复输出的抑制
3.hacking2：模型把疾病列表全部输出
-如果单独惩罚FP，如果惩罚太弱，难以起到抑制效果；如果太强，会导致recall下降，不符合临床场景。所以考虑使用F1分数，把FN/FP放到同一个尺度上。一开始的设计比较简单，大于某个阈值就给分，否则不给。
4.hacking3：二值奖励导致reward std下降，虽然总优势没有消失，但是丢失了同侧的质量差异 -> 连续F1
5.编辑距离的引入时机？
```

2.研究的motivation/项目介绍
```
我独立完成了一个 SLO 眼科影像报告生成系统，输入眼底检查图像，输出包含诊断、证据和镜下所见的结构化报告。

项目最初只有图像和对应的诊断标签，缺少配套报告标注。因此，我利用 GPT-5 合成报告训练数据，通过 SFT 完成模型冷启动。随后，将医生对候选报告的选择、编辑和标签确认转化为可复用的奖励参照，通过 GRPO 进行多轮后训练。

其中，我重点迭代了奖励设计，处理重复输出、过度报病和组内奖励区分度不足等问题。首轮更新后，报告首次采纳率从 67.81% 提升到 91.14%，后续审核耗时中位数从 34.2 秒降到 13.4 秒。
```
