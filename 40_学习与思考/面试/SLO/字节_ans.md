**4. “MoE 了解吗？”**

> MoE 是混合专家架构。在常见的稀疏 MoE 中，一个层里包含多个专家网络，Router 根据当前 token 的表示选择 Top-k 个专家，再对专家输出进行加权组合。
> 
> 它可以增加模型的总参数容量，同时控制每个 token 实际参与计算的参数量。训练时需要关注专家负载均衡，避免大量 token 集中到少数专家；分布式运行时还需要考虑专家之间的通信开销。
> 
> 总参数量和激活参数量需要分别理解。总参数量影响权重存储，激活参数量反映单个 token 使用的部分计算路径。我们使用的 Qwen3-VL-32B 属于 Dense 版本。

机制可参考[稀疏 MoE 原始论文](https://arxiv.org/abs/1701.06538)，模型类型见 [Qwen3-VL 官方模型说明](https://huggingface.co/Qwen/Qwen3-VL-32B-Instruct)。

**5. “你是怎么做 SFT 的？”**

> 我们首先构造图像到结构化报告的监督数据。已有数据提供眼底图像和 27 类诊断标签，医生为每类疾病编写代表性的 SLO 描述语句。报告合成时，将诊断标签、分类模型的预测概率和医生语料组合起来，交给 GPT-5 生成结构化报告，再由眼科团队审核。
> 
> SFT 样本的输入包括图像和提示词，输出是审核后的参考报告。加入空间特征后，输入还包含专用视觉模型提供的空间表示。
> 
> 实现上使用 ms-swift 和 LoRA，rank 为 8，alpha 为 32，学习率为 \(10^{-5}\)，采用 BF16。语言模型的 LoRA 和外部空间特征投影适配器参与训练，上游分类模型与原生视觉模块保持冻结。
> 
> 这个阶段让模型学习报告格式、疾病表达，以及如何使用分类先验和图像信息生成报告。

如果继续追问 LoRA，可以补：

> LoRA 将权重更新写成低秩形式 \(\Delta W=\frac{\alpha}{r}BA\)，训练低秩矩阵，保留原有基础权重。我们选择 rank 8，主要考虑适配能力和训练资源之间的平衡。

**7. “SFT 的损失是什么？写一下公式或者实现。”**

> 对报告生成任务，常见的 SFT 目标是参考报告 token 的负对数似然，也就是交叉熵。
> 
> 给定图像、提示词和已经出现的报告内容，模型预测下一个 token。训练时采用 teacher forcing，并根据监督 mask 选择需要计算损失的位置。

常见的 token 平均形式为：

\[ \mathcal L_{\mathrm{SFT}} = -\frac{1}{\sum_t m_t} \sum_t m_t \log p_\theta(y_t\mid I,x,y_{<t}) \]

其中，\(I\) 为图像及相关视觉条件，\(x\) 为提示词，\(m_t\) 表示该位置是否参与监督。

如果要求用 NumPy 手写交叉熵，可以写：

```
import numpy as np

def cross_entropy(logits, labels):
    # logits: [N, C]，labels: [N]，-100 表示忽略
    valid = labels != -100
    z = logits[valid].astype(np.float64)
    y = labels[valid]

    if len(y) == 0:
        raise ValueError("No valid labels")

    z = z - z.max(axis=1, keepdims=True)
    log_probs = z - np.log(
        np.exp(z).sum(axis=1, keepdims=True)
    )
    return -log_probs[np.arange(len(y)), y].mean()
```

口述解释：

> 我先减去每行最大值，保证指数运算稳定，再计算 log-softmax，取真实类别对应的负对数概率并求平均。用于语言模型时，还需要先完成预测位置和标签位置的错位对齐，再展平有效 token。

交叉熵定义见 [PyTorch 官方文档](https://docs.pytorch.org/docs/2.9/generated/torch.nn.CrossEntropyLoss.html)。

**8. “GRPO 是怎么做的？”**

> 我们以完成 SLO 适配的模型作为初始策略。训练时，对同一个图像和提示词采样一组候选报告，为每份报告计算奖励，再根据组内奖励的相对大小计算优势。
> 
> 得分高于组内平均水平的候选获得正优势，得分低的候选获得负优势。随后，通过带裁剪的策略优化目标更新模型，并利用 KL 正则控制模型相对参考策略的偏移。
> 
> 项目配置中，每个输入生成 8 个候选，采样温度为 1.2，top-p 为 0.97，学习率为 \(5\times10^{-6}\)，KL 系数为 0.01。
> 
> 每轮更新前，我们会合并已有 LoRA 权重，再初始化新的适配器进行下一轮训练。

如果追问优势计算：

\[ A_i= \frac{r_i-\operatorname{mean}(r)} {\operatorname{std}(r)+\epsilon} \]

> 这里的比较范围是同一个输入对应的一组候选。组内相对奖励直接提供优势估计，因此可以省去额外的价值模型。

机制见 [GRPO 原始论文](https://arxiv.org/html/2402.03300v2)，项目参数对应[当前 GRPO 启动脚本](D:/workspace_codex/projects/paper/project/qwen/grpo/grpo_s1_v7_merged.sh)。

**9. “奖励怎么衡量？模型打分还是人工标注？”**

> 医生提供参考诊断和参考报告，训练时通过规则自动计算奖励。奖励分为诊断、文本和结构三个分量，当前配置采用等权相加。
> 
> 诊断分量先从候选和参考报告中提取疾病集合，计算单份报告的 F1，再映射为 \(2F_1-1\)。
> 
> 文本分量比较双方的“SLO 检查情况”段，计算长度归一化的编辑相似度。
> 
> 结构分量考虑诊断覆盖、诊断与证据条目的对应关系、证据强度标签，以及额外疾病和重复证据等问题。
> 
> 这样可以将医生确认的报告转换为自动训练信号。

可以补出两个核心公式：

\[ r_{\mathrm{score}}=2F_1-1 \]\[ r_{\mathrm{edit}} = 1-\frac{d_{\mathrm{Lev}}(s,\hat s)} {\max(|s|,|\hat s|)} \]

**注意区分计算单位**：奖励中的 F1 针对单份候选报告；测试结果中的 micro-F1 汇总整个数据集的 TP、FP、FN。

**10. “编辑距离具体是什么？怎么算？”**

> 我们使用 Levenshtein 编辑距离，表示把一个字符串转换成另一个字符串，最少需要多少次插入、删除和替换操作，每次操作的代价为 1。
> 
> 用动态规划计算。设 \(dp[i][j]\) 表示前一个字符串前 \(i\) 个字符，转换成后一个字符串前 \(j\) 个字符的最小代价。每个位置分别考虑删除、插入和替换，取三者最小值。
> 
> 项目中再除以两个字符串长度的最大值，得到归一化距离，最后用 1 减去距离作为文本奖励。优先比较 SLO 描述段，任一方缺少该段时，比较完整报告。

状态转移：

\[ dp[i][j]= \min \begin{cases} dp[i-1][j]+1\\ dp[i][j-1]+1\\ dp[i-1][j-1]+\mathbf 1[a_{i-1}\ne b_{j-1}] \end{cases} \]

> 时间复杂度是 \(O(nm)\)。使用两行数组可以把额外空间降到 \(O(m)\)。这个指标衡量字符层面的修改量，医学内容的质量由诊断指标和医生审核共同评价。

定义见 [NIST 编辑距离说明](https://xlinux.nist.gov/dads/HTML/Levenshtein.html)。

**11. “同一个输入怎么生成八份不同报告？要改图片或者 Prompt 吗？”**

> 八份候选通过随机解码产生。每份候选使用相同的图像、空间特征和 Prompt，生成过程中根据 token 概率分布进行采样，所以后续生成路径会出现差异。
> 
> 温度控制分布的平滑程度，top-p 控制参与采样的候选 token 范围。我们当前 GRPO 配置使用温度 1.2、top-p 0.97，每个输入采样 8 次。
> 
> 八份候选可以出现相同内容，采样提供的是多样性机会。训练时再通过奖励比较这些候选的质量。

不要把“不同随机采样”讲成“保证生成八份不同文本”。

**12. “医生选八份报告，和 GRPO 的数据构造是什么关系？”**

> 数据收集和训练分别进行。
> 
> 数据收集阶段，模型为一张图像生成 8 份候选，医生选择其中一份并修改，形成最终参考报告和确认后的诊断标签。这些信息保存为训练样本。
> 
> GRPO 阶段，模型根据样本中的输入重新采样一组候选，再与参考信息比较并计算奖励。数据字段里的 `solution` 提供奖励计算所需的参考答案。
> 
> 这样，医生的选择和修改产生监督依据，训练阶段的组内采样产生策略更新所需的候选。

这一题要把两次“八份候选”各自发生的阶段说清楚。

**13. “全局、局部分支具体在做什么？怎么融合？”**

==🟠**16. “你怎么理解多实例学习？项目里怎么使用？”**==

> ==🟠多实例学习把一个样本表示为一组实例，也叫一个 bag。监督标签通常提供在 bag 层面，每个实例的标签可以未知。==
> 
> ==🟠在这个项目中，一张眼底图像可以看成一个 bag，局部 patch 是实例，整张图像的疾病标签用于监督最终的分类结果。模型需要学习哪些局部特征对当前疾病判断有贡献。==
> 
> ==🟠我们通过类别级 Query 对局部 patch 做注意力聚合，再预测整图的疾病标签。这种方式可以利用局部细节，同时保留整图层面的监督。==

MIL 的标签关系可参考[多实例学习论文](https://icml.cc/2009/papers/422.pdf)。

**17. “评测指标是什么？报告的召回率怎么理解？”**

> 自动评测的主要指标是从报告中提取疾病标签后的 micro-precision、micro-recall 和 micro-F1。先把生成报告映射到统一的 27 类疾病集合，再跨图像和类别汇总 TP、FP、FN。
> 
> 这里的召回率表示参考诊断中的疾病，有多少在生成报告中被正确报告。文本层面还使用 ROUGE-L、BLEU-4 和 METEOR。
> 
> 医生审核阶段关注首次采纳率、镜下所见修改率和审核时间。首次采纳率对应医生从候选报告中选出一份，并直接采用的病例比例。
> 
> 上游分类模型则另外评估各类别 AUROC。

结果追问可以这样接：

> 固定测试集上，专科适配模型的诊断 micro-F1 为 0.751，precision 为 0.733，recall 为 0.769。三批医生审核中，首次采纳率分别为 67.81%、91.14% 和 91.06%，审核时间中位数分别为 34.2、18.1 和 13.4 秒。

**18. “有没有用 Dice？为什么不做检测或者分割？”**

转录中这个指标的识别有歧义，以下按面试官问 Dice 来准备：

> Dice 通常用于衡量预测区域与参考区域的重叠程度，需要像素级分割结果和对应标注。我们当前输出疾病标签和报告，主要使用诊断一致性与报告指标进行评估。

**23. “奖励函数具体怎么迭代？Reward hacking 怎么处理？”**

> 我们遇到过三类问题。
> 
> 第一类是重复输出同一种疾病。定位时发现，诊断结果转成集合后，重复次数会被消掉，诊断集合指标无法反映文本中的重复程度。这个问题要求在去重前保留次数信息，再单独处理重复输出。
> 
> ==🟠第二类是输出大量疾病。增加误报惩罚后，模型又出现报告疾病变少、召回下降的趋势。因此我们调整了诊断正确性与额外疾病惩罚之间的平衡。==
> 
> 第三类是二值诊断奖励的区分度不足。不同质量的候选只要同时达到阈值，就获得相同分数。因此我们采用连续奖励 \(2F_1-1\)，让部分正确和完全正确的候选得到不同分数。
> 
> 当前结构奖励还对超过两个的额外诊断施加超线性惩罚，惩罚项为：
> 
> \[ 0.08\cdot\max(0,FP-2)^{1.5} \]
> 
> 调整后需要同时查看诊断 precision、recall、F1、组内奖励分布和输出样例，确认优化方向符合预期。

**这一题有一个源码细节需要你补齐**：当前奖励代码仍用集合解析诊断，也有重复证据的计数项。你原先提到“重复诊断问题已经修复”，应准备对应修改版本和具体代码位置，方便准确回答修复过程。

**24. “100 个球，轮流拿，怎么保证自己赢？”**

转录中的完整题面缺失。按**每次取 1–11 个、A 先手、取走最后一个获胜**来回答：

> A 先取 4 个，让剩余数量变成 96，也就是 12 的倍数。
> 
> 后续 B 每次取 \(x\) 个，A 就取 \(12-x\) 个。这样每轮双方合计取走 12 个，A 操作后剩余数量始终为 12 的倍数。
> 
> 最后剩 12 个时，B 取 1–11 个，A 可以取走剩余全部球，因此获胜。
> 
> 这里的不变量是：每次 A 操作后，剩余球数为 12 的倍数。

如果题目规定每次取 **1–10 个**，对应周期是 11，A 应先取 **1 个**。答题前先确认取球范围和获胜条件。

**25. “火柴拼正方形，先说策略，再实现。”**

口述可以这样回答：

> 我使用回溯，把每根火柴分配到四条边之一。
> 
> 首先计算总长度，检查是否能被 4 整除，得到目标边长；再检查最长火柴是否超过目标边长。随后将火柴按长度降序排列，让较难放置的火柴优先处理。
> 
> 搜索状态包含当前处理的火柴下标，以及四条边已经累计的长度。每一步尝试把当前火柴放到一条边上，超过目标长度就剪枝；递归失败后撤销放置，再尝试其他边。
> 
> 四条边当前长度相同时，对当前火柴产生的搜索状态具有对称性，可以跳过重复尝试。所有火柴放置完成，并且四条边达到目标长度时返回成功。
> 
> 未剪枝的搜索上界为 \(O(4^n)\)，排序和对称剪枝可以减少实际搜索量。

参考实现：

```
def makesquare(sticks):
    if len(sticks) < 4:
        return False

    total = sum(sticks)
    if total <= 0 or total % 4:
        return False

    target = total // 4
    sticks = sorted(sticks, reverse=True)

    if sticks[0] > target:
        return False

    sides = [0] * 4

    def dfs(i):
        if i == len(sticks):
            return all(s == target for s in sides)

        tried = set()

        for k in range(4):
            if sides[k] in tried:
                continue
            if sides[k] + sticks[i] > target:
                continue

            tried.add(sides[k])
            sides[k] += sticks[i]

            if dfs(i + 1):
                return True

            sides[k] -= sticks[i]

        return False

    return dfs(0)
```
