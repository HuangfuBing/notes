## 为什么旅行场景具有研究价值

旅行规划承载的是有约束的多步决策与工具使用问题。这个场景具有四个适合算法验证的性质：

- 用户约束可拆解，如日期、预算、地理位置、交通方式和偏好。

- 工具之间存在依赖，前一步的返回值会影响后续参数和选择。

- 执行结果可检查：把路线、时间安排和工具返回逐项对应，评价方案的一致性与可执行性。

- 可比较质量与资源消耗，如完成率、约束满足、冗余调用、时延和单任务成本。

项目动机以“平台经验 → 算法问题 → 场景选择”展开。个人兴趣可以自然补充为场景熟悉度，技术目标随着实现和实验逐步明确。

> 同时，模块化结构便于分别分析识别、标签选择和报告表达三个环节，让后续优化更有针对性。

## 09 如何判断模型更新后变好还是变坏

>

评估材料按“指标定义、数据划分、版本对照、逐类结果”准备。macro、micro 或 sample F1 的选择与实验表保持一致。

## 11 影像描述的好坏如何评价

>

> 在数据构造阶段，我们结合医生整理的影像特征语料库生成报告，再交由医生做质量控制，为模型提供专业的表达起点。

后续可以将医生评分细化为事实准确性、关键信息覆盖和表达质量三项，进一步建立描述评价与修改负担之间的联系。

## 12 这是离线后训练吗

> 从反馈收集和模型更新方式看，是分批收集医生修订，再离线进行训练。从 GRPO 的训练过程看，模型会针对这些输入重新采样候选报告，再计算奖励并更新策略。

GRPO 从旧策略采样一组输出，计算奖励和相对优势后更新策略。回答时分别说明反馈数据的收集方式与训练轨迹的采样方式。[DeepSeekMath 原论文](https://arxiv.org/html/2402.03300v3)

GRPO 的奖励可以来自规则、奖励模型或环境反馈；本项目使用医生修订报告作为诊断与描述奖励的参考。[TRL GRPO 文档](https://huggingface.co/docs/trl/grpo_trainer)

## 19 人工反馈的数据量够吗 如何判断

> 反馈数据用于 SFT 模型上的增量优化。SFT 阶段约有 1.2 万份报告，随后每轮收集约 700 份医生反馈，共完成三轮更新。
>
> 数据规模是否合适，我主要看错误类型覆盖、评估指标变化以及新增数据的边际收益。我们尝试过增加或增强数据，当时指标收益趋于平稳，因此进一步把重点放在反馈质量与奖励设计上。
>
> 当前实验中，这个数据规模支持了诊断与报告使用指标的改进，说明小规模、高质量的领域反馈具有实际优化价值。

数据量回答配一张样本规模与指标表，并说明反馈覆盖的疾病、错误类型和采样方式。重点讲清数据怎样支持模型改进。

## 29 请介绍 Transformer 的网络结构

> 以原始 Transformer 为例，它由编码器和解码器组成。输入 token embedding 加入位置信息后，编码器每层经过多头自注意力和前馈网络，各子层都有残差连接与层归一化。
>
> 解码器每层先做带因果掩码的自注意力，避免看到未来 token；再做交叉注意力，其中 Query 来自解码器，Key 和 Value 来自编码器输出；之后经过前馈网络。最终隐状态经过线性映射得到词表 logits，再形成下一个 token 的分布。
>
> 注意力的核心是用 Q 和 K 的匹配程度对 V 加权，多头机制在多个表示子空间中分别计算。原始结构使用 Post-LN，现代实现可能调整归一化位置；仅使用解码器的语言模型也没有这里的编码器交叉注意力模块。

核心公式：`Attention(Q,K,V) = softmax(QK^T / sqrt(d_k) + mask)V`。多头结果拼接后再做线性投影。[Transformer 原论文](https://arxiv.org/html/1706.03762v7)

主体回答控制在约一分钟，先给清晰的网络流程。追问时再展开 QKV、缩放、复杂度和位置编码。

## 30 常见后训练算法有哪些 原理是什么

> 我会按监督信号区分。SFT 使用示范答案，在给定正确前缀的条件下优化目标 token 的交叉熵。偏好优化使用好坏回答对，DPO 是代表方法。强化学习则根据模型采样结果获得奖励，再调整策略，常见方法包括 PPO 和 GRPO。
>
> PPO 通常借助价值模型估计优势，并通过截断的概率比目标限制更新；GRPO 用同一输入的一组候选奖励构造相对优势，省去单独的价值模型。DPO 直接优化偏好对相对于参考模型的概率关系，不需要在标准训练流程中不断在线采样。
>
> 此外还有蒸馏。离线轨迹蒸馏学习教师生成的示范；on-policy 蒸馏让学生在自己生成的前缀上接受教师监督，重点缓解训练与实际生成时的分布差异。我实际做过的部分主要是 SFT、轨迹蒸馏和 GRPO，其他方法按理解展开。

PPO 的截断目标见[原论文](https://arxiv.org/abs/1707.06347)；GRPO 的组内优势见[DeepSeekMath](https://arxiv.org/html/2402.03300v3)；DPO 的偏好目标及 KL 正则推导见[DPO 原论文](https://arxiv.org/html/2305.18290v3)；学生采样上的蒸馏见[GKD 原论文](https://arxiv.org/abs/2306.13649)。

按监督信号介绍 SFT、偏好优化和 RL，再用蒸馏连接知识迁移与训练目标，形成清楚的分类逻辑。

# 技术选择的专业解释与追问答案

## 为什么选择 4B 小模型

> 我选择 4B，是为了研究受约束模型在明确任务范围内的能力提升。这个规模适合反复进行数据、奖励和训练策略实验，便于观察后训练带来的变化。
>
> 成本评价以成功完成一次任务为单位，综合推理、工具调用和重试开销。这样可以把模型规模的选择与实际任务效率联系起来。

把资源效率作为设计目标，把任务质量与单任务开销作为评价维度。实测结果按相同任务集和运行条件展示。

## 为什么使用教师轨迹蒸馏

> 教师轨迹为复杂工具任务提供调用顺序、参数构造和结果使用的示范，可以提高训练数据的构造效率。我再通过协议、执行和任务一致性检查筛选轨迹，形成学生模型的训练数据。
>
> 本项目采用教师生成轨迹上的离线蒸馏。on-policy 蒸馏则在学生生成的序列上引入教师反馈，两种方式对应不同的训练状态来源。

教师接口返回文本时，重点讲轨迹级监督；接口支持概率分布时，再展开 token 级分布匹配目标。

## 为什么需要三层数据过滤

> 各层过滤针对不同错误。格式层检查消息角色、工具名称和参数结构；执行层检查调用能否完成、参数引用是否有效；任务层检查回答是否满足约束、是否使用工具证据。
>
> 这样可以把低成本、可确定判定的问题先过滤，再把较复杂的质量判断交给更昂贵的评价方式。

按实际实现填写三层过滤的名称、检查对象和保留比例。每层用一个代表性样本解释其价值。

## 为什么要重视工具环境的稳定性

> 稳定的工具环境让模型比较具有一致的交互条件，也让训练奖励更容易归因到策略行为。环境版本、输入条件和失败处理方式，是我关注的关键因素。
>
> 环境吞吐同时影响 rollout 效率。因此，工具环境既服务于可靠评估，也服务于训练规模扩展；扩展方案还会综合算力、数据和工具配额。

后续环境优化可以围绕工具 schema、版本记录、结果回放和超时统计展开，为可复现评估提供支持。

## 为什么用模型模拟部分票务工具

> 我使用模拟票务工具，是为了以可控成本建立多工具训练环境，重点验证调用协议、参数传递和多步决策。真实 API 则承接外部信息查询，两类工具承担不同的验证任务。
>
> 面向真实票务能力时，下一阶段接入真实库存和价格服务，沿用现有协议与评价流程进行验证。

模拟环境的后续优化重点是固定测试情境、记录返回结果并采用独立评价。实验展示按真实服务与模拟环境分组说明。

## 为什么使用 LLM judge

> 我把奖励分为可确定检查的协议项，以及需要综合判断的任务质量项。前者用规则评估格式与参数，后者用 rubric 引导 LLM judge 评价约束满足和工具证据使用。
>
> 分析训练波动时，我会联合查看生成样本、工具状态和奖励分量。judge 的评价质量可以进一步通过重复评分与人工对照检验。

后续评价验证选取固定轨迹，比较重复评分与人工判断，并分析答案长度、表达方式和证据使用对评分的影响。

## 为什么选用 GRPO 而不继续 SFT 或使用 DPO

> GRPO 与我们已有的奖励形式匹配。SFT 建立基本报告能力后，模型能够生成多份候选，我们用诊断指标和医生参考评价这些候选，再利用组内相对信号优化策略。
>
> 这套方法便于把可计算的任务目标直接纳入训练，同时省去独立价值模型。继续 SFT 和 DPO 分别提供示范学习与偏好学习的对照方向，可以进一步检验不同反馈利用方式的收益。

后续对照使用同一批反馈数据比较继续 SFT 与 GRPO，分别观察数据增量和训练目标带来的贡献。

## 为什么把诊断奖励改成连续 F1

> 连续 F1 保留了候选报告之间更细的诊断质量差异，使奖励排序更贴近实际表现。它解决的是阈值化之后候选容易得到相同分数的问题。
>
> 对 GRPO 而言，我关注的是组内候选的有效区分：哪些报告更好、差距来自哪些标签。分析时结合奖励打平比例、候选排序和总奖励分量，判断训练信号的质量。

二值奖励适合清晰的成败判断，连续奖励适合表达分级质量。多项奖励组合时，按总奖励计算相对优势，同时检查各分量的区分作用。[GRPO 奖励与优势计算](https://huggingface.co/docs/trl/grpo_trainer)

## 如何解释误诊与漏诊的权衡

> FP 对应疾病误报，FN 对应疾病漏报。两类错误的代价结合具体病种和医生工作流程确定。
>
> F1 用于综合评价 precision 和 recall；临床偏好进一步通过类别权重、召回约束或任务目标体现。这样可以把模型优化指标与具体使用要求联系起来。

回答顺序是“错误定义 → 业务代价 → 指标选择 → 训练目标”。具体权重与阈值依据病种和医生要求确定。

## 为什么使用医生语料库构造报告

> 医生语料库为报告构造提供专业的描述框架。原始图像与疾病标签构成数据基础，典型影像特征帮助组织专业表达，医生审核确认描述与当前图像的对应关系。
>
> 这让领域知识、图像证据和质量控制各有明确职责，共同支持高质量的报告数据。

用一例医生修订前后的报告，展示语料库如何改善专业表达，以及审核如何确认图像与描述的对应关系。

## 为什么保留专用模型而不是完全端到端

> 专用模型可以充分使用图像与疾病标签监督，提供适应 SLO 模态的判别信息；大模型融合原始图像、预测分数与视觉特征，完成报告生成。
>
> 两阶段结构让领域判别和生成能力形成协同，也便于分别定位各环节的问题。方案价值通过诊断指标、报告质量和模块消融展开。

骨干选型围绕数据规模、训练成本和实际实验结果解释。说明当前 SSM 或 Mamba 实现承担的视觉建模任务，再按追问介绍已比较的方案。

## 为什么每轮使用新的 LoRA adapter

> 新的 LoRA adapter 服务于低成本迭代与版本管理。每轮在上一版模型上训练增量参数，评估通过后保留更新，并保存相应 checkpoint，支持版本追踪与恢复。
>
> 原有能力保持由跨版本评估来检查，版本保留由诊断与报告指标共同决定。这样把参数更新、效果验证和部署管理连接起来。

LoRA 通过低秩参数更新降低可训练参数量，属于微调方式；遗忘控制与版本回退属于另外的评价和工程问题。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

## 从医疗项目怎样迁移到风控

> 我的医疗项目经验可以迁移到“专用判别模型＋大模型解释＋人工反馈”的风控工作流。专用模型提供领域判别信息，大模型结合可用行为证据生成便于审核的解释，人工反馈继续推动模型评价与迭代。
>
> 我会从预测质量、解释证据和审核效率三个维度组织验证。解释中的关键判断需要对应具体行为与模型依据，人工审核收益则通过耗时和错误率等指标衡量。
>
> 初期先确定业务目标，再比较专用模型、规则解释与大模型方案，明确每个模块带来的实际价值。

迁移回答采用方案语态，重点展示已有方法如何服务新业务：领域信息融合、解释评价、人工反馈和实验验证。

# 后训练算法追问速查

## SFT 和 teacher forcing 到底在优化什么

> 给定输入和目标回答，训练时使用目标回答的真实前缀，预测下一个目标 token，并最小化负对数似然。训练目标通常是有效监督位置上的交叉熵之和或平均值。
>
> 监督范围由训练目标、消息模板和标签掩码共同决定。实现时逐项确认用户消息、工具返回与助手动作对应的监督位置。

参考：[TRL SFT 文档](https://huggingface.co/docs/trl/sft_trainer)。

## 工具调用的 loss 为什么会被屏蔽

> 对应 token 的 labels 被设置为 ignore index，例如 −100，交叉熵计算会跳过这些目标位置。
>
> 我的排查重点是消息到 token 标签的转换链路：从原始工具调用格式，检查到模板展开和监督掩码，确认工具动作获得预期的训练信号。这个案例体现了 token 级训练检查对目标能力优化的价值。

PyTorch 的交叉熵支持用 ignore index 排除相应目标位置。[PyTorch 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html?highlight=criterion)

## PPO 的核心目标如何解释

> PPO 用新旧策略在已采样动作上的概率比，结合优势估计形成策略梯度目标，再对概率比进行截断，控制策略更新幅度。通常还训练价值函数来辅助优势估计。
>
> PPO clip 关注新旧策略之间的更新幅度；LLM 训练中的参考模型 KL 惩罚关注相对参考策略的偏移，两者分别承担更新控制与策略正则的作用。

简化目标：`E[min(r_t A_t, clip(r_t, 1−ε, 1+ε) A_t)]`，其中 `r_t = πθ(a_t|s_t) / πold(a_t|s_t)`。[PPO 原论文](https://arxiv.org/abs/1707.06347)

## GRPO 的优势与 token 信用分配如何解释

> 在常见终局奖励版本中，对同一输入采样多个候选，用组内奖励均值作基线，并按标准差归一化。一个候选的生成 token 共享序列级优势，再通过各自的概率参与优化。
>
> 这里提供的是序列级评价信号。在多步 Agent 中，模型生成的动作 token 承担策略优化，工具返回则提供后续决策的环境信息。

示意优势：`A_i = (r_i − mean(r)) / (std(r) + ε)`。实际实现可能使用不同的归一化或损失聚合形式，应按所用训练器配置回答。[GRPO 原论文](https://arxiv.org/html/2402.03300v3)

## DPO 有没有 KL 约束

> 标准 DPO 从带参考策略 KL 正则的奖励最大化目标推导而来，并把奖励重参数化为策略与参考策略的概率关系。这种正则作用体现在包含参考模型的偏好损失中。
>
> 训练数据通常是同一输入下的 chosen 和 rejected 回答，标准流程直接优化这些偏好对相对参考模型的概率关系。

记忆形式：`−log sigmoid(β × [log(πθ(y+)/πref(y+)) − log(πθ(y−)/πref(y−))])`，所有概率均以同一个输入为条件。[DPO 官方文档](https://huggingface.co/docs/trl/dpo_trainer)

## OPD 与离线轨迹蒸馏有什么区别

> 区别首先在训练状态的来源。离线轨迹蒸馏使用教师预先生成的序列；on-policy 蒸馏由学生生成序列或前缀，再在这些状态上获得教师监督。
>
> 教师提供文本时，可以组织轨迹与反馈监督；支持概率分布时，可以进一步构造 token 级分布匹配目标。与任务奖励组合，是我后续关注的训练方向。

教师负责提供监督，学生策略接受更新。参考：[GKD 官方文档](https://huggingface.co/docs/trl/gkd_trainer)。

# 表达习惯优化

## 把表达集中到判断与贡献

你的项目材料已经覆盖数据构造、模型训练、奖励设计和场景验证。表达训练的重点，是让面试官更快听到你的技术判断、个人贡献和最有分量的证据。

| 表达场景 | 推荐句式 | 展示的能力 |
| - | - | - |
| 建立个人定位 | “我专注 LLM 后训练和 Agent 算法，做过医疗多模态与平台 Agent 实践。” | 方向清晰 |
| 回答设计原因 | “我选择这个结构，主要依据是数据条件和消融结果。” | 技术判断 |
| 介绍项目目标 | “项目解决的是多工具任务中的策略训练与执行评价问题。” | 问题定义 |
| 解释实验结论 | “在相同条件下，A 相比 B 的 X 指标提高了 Y。” | 实验论证 |
| 描述个人职责 | “我负责数据构造、奖励设计和训练验证三个核心环节。” | 贡献清楚 |
| 展示排错能力 | “我沿着消息格式、token 标签和生成行为定位了监督掩码问题。” | 因果分析 |
| 解释模块作用 | “消融量化模块收益，注意力分析观察信息交互。” | 证据组织 |
| 表达结果范围 | “这个收益主要体现在 X 类任务，评价条件是 Y。” | 准确表达 |
| 回答后续方向 | “下一步用 X 对照验证 Y，重点观察 Z 指标。” | 研究规划 |
| 组织长回答 | “核心是两个决策，我分别说明依据和结果。” | 信息组织 |
| 提出反问 | “团队用哪些指标判断这类方案值得继续投入？” | 业务理解 |

保留自然停顿，用“原因是、实验表明、对应到任务、下一步验证”等连接词组织逻辑。每句话围绕一个明确判断展开。

## 按问题类型选择回答结构

**确认性问题**用事实和关键配置直接回答，约 10 到 20 秒。例如“是的，下游是 32B 级模型，采用 LoRA 微调”。

**设计原因**用“选择 → 依据 → 收益”展开，约 40 到 60 秒。例如“专用模型提供领域判别信息，大模型完成融合与报告生成，消融实验支持了这种协同”。

**实验结论**用“结论 → 对照 → 指标 → 任务范围”展开，约 45 到 75 秒。机制分析配代表性样本，效果结论配实验结果。

**项目介绍**用“技术定位 → 任务价值 → 核心决策 → 代表成果”展开，约 60 到 90 秒，个人职责融入具体动作。

**技术原理**先定义，再解释核心机制，最后点明和相近方法的区别。公式在被追问或能明显帮助理解时展开。

时长用于建立回答节奏。面试官追问时立即切换到当前问题，回答清楚后再衔接主线。

## 四组可直接练习的改写

### 从兴趣动机到技术问题

原表达：

> 因为我比较喜欢旅行，而且 Agentic RL 发展很快，所以想自己亲自试一下。

改写：

> 我结合阿里云路由与评测经验，在 IAH 上开展小模型多工具能力探索。旅行规划具有显式约束和工具依赖，适合验证策略对环境反馈的利用，因此成为我的实验场景。

如果追问项目起点，可以自然说明：“个人兴趣帮助我熟悉旅行场景，实习与训练经验进一步明确了小模型多步执行的技术目标。”

### 从过程堆叠到直接回答

原表达：

> 我们先有数据，然后做清洗，再构造报告，再训练，然后医生修改，再回流。

改写：

> 我负责把 SLO 领域判别、报告生成和医生反馈组织成一套模型迭代流程。专用模型提供视觉判断，大模型生成报告，医生修订转化为训练信号，三部分共同服务于可使用的诊断报告。

被问到实现细节时，再补数据和训练步骤。

### 从宽泛归因到可检查结论

原表达：

> loss 虽然下降，但是模型越来越不愿意调用工具，后来发现是格式的问题。

改写：

> 我定位了工具调用训练中的监督掩码问题。通过对照原始消息、模板输出和 token 标签，确认工具动作的监督位置被屏蔽，并据此修复格式适配。这个案例体现了我从训练信号解释生成行为的能力。

案例结尾优先接修复前后的工具调用指标，形成“现象 → 定位 → 修复 → 结果”的完整证据。

### 从泛泛自评到准确的贡献表达

原表达：

> 整个项目比较费时间，数据构造和奖励迭代花了很多时间。

改写：

> 我的核心贡献集中在数据与奖励两个环节：把图像和疾病标签转化为可审核的报告训练数据，并通过生成样本分析迭代诊断奖励。前者建立领域监督，后者把诊断目标转成有效的优化信号。

把工作量转化为技术价值：明确解决了什么问题、作出了什么决策、留下了什么结果。

## 三类展示专业判断的表达

**结果陈述：**

> 在相同数据和评价条件下，A 相比 B 的 X 指标提高了 Y，主要收益体现在 Z 类任务。这项结果支持了我采用该模块的设计。

**机制分析：**

> 我观察到 X，并将 Y 作为重点机制假设。接下来通过 Z 对照观察指标变化，检验它对结果的贡献。

**后续验证：**

> 已完成实验覆盖 A。针对您提出的 B，我下一步会设置 C 对照，重点观察 D 指标，用来回答这个更具体的问题。

结果陈述连接实验，机制分析连接假设，后续验证连接行动。用准确的动词与时态，让研究判断清楚、表达有力。

## 三轮口述练习

第一轮练“结论先行”：随机抽取十个问题，每题两句话。第一句给判断，第二句给最关键的依据。

第二轮练“证据落地”：每题扩展到一分钟，选一个代表实验或案例。回听时检查个人决策、比较基线和结果意义是否清楚。

第三轮练“追问展开”：在项目介绍中随机加入“为什么选择这个方案”“指标怎样计算”“你负责哪部分”“证据是什么”。先直接回答，再用一个具体例子展开。

每轮检查五件事：定位清楚、判断直接、证据具体、贡献明确、收束有力。
